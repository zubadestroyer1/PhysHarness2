# PhysHarnessV2 implementation specification

Approved September 14, 2026. The implementation preserves the full research roadmap; wave qualification requires evidence and is separate from shipping code. Research references: [physics](../outputs/2026-09-14-physics-harness-research.md) and [agent harnesses](../outputs/2026-09-14-coding-harness-comparison.md).

## Binding decisions

Managed infrastructure first, followed by a self-hosted deployment path. Open-source Apache-2.0 code and reviewed public results; private authenticated research workspaces. Both finite-dimensional quantum information and classical mathematical physics start together. First production qualification is 128 active workers over 72 hours; 1,000-worker qualification follows. These are acceptance targets, not implemented capacity claims.

Models choose methods, decomposition, collaboration, optional skills, and research programs. There is no obligatory proof scaffold. Models, native agent runtimes, prover backends, and VM providers have independent adapters. Routine allocations are automatic inside an explicit experiment envelope. Helpers, persistent collaborators, and competing branches have distinct lifecycles. Native opaque spawning is disabled when its descendant costs cannot be governed.

Experts review target meaning, important new definitions, and public scientific claims. Mechanically checked intermediate results under reviewed definitions need not await expert approval. Do not fabricate human review or novelty. Formal acceptance, semantic review, numerical evidence, assumptions, and novelty are separate dimensions.

## Architecture and contracts

Python 3.12/FastAPI/Pydantic/SQLAlchemy/Alembic; PostgreSQL with full-text and pgvector retrieval; Temporal owns execution; a transactional outbox connects PostgreSQL commands to workflows. Content-addressed S3 artifacts, local development storage, E2B VM workers, AWS ECS/RDS control plane, React/TypeScript console, OpenTelemetry and Langfuse-compatible tracing, Terraform and Docker. Later Kubernetes, self-hosted VM isolation, and Ray/KubeRay deployment paths do not replace canonical scientific storage. Evaluate existing lifecycle controllers and VM isolation before building a custom Firecracker host pool.

Canonical objects: Campaign, ProblemRevision, Experiment, ResearchBranch, AgentSession, Task, Artifact, Claim, VerificationReceipt, ReviewDecision, ResourceLedger, ResearchProgram. Scientific revisions are immutable; mutable execution records use optimistic revisions. Commands have idempotency keys with input fingerprints. Task ownership uses leases and fencing. Events are append-only, large outputs are artifact references. Cloud credentials and receipt-signing authority are outside generated code.

HTTP API under /v1, Python client and MCP share application services. Problem ingestion/review; experiment start/pause/resume/cancel/export; research spawn/fork/mail/subscription/resource request; artifact submission/retrieval; proof checking; knowledge retrieval; review and evaluation operations. Runtime adapters start/continue/interrupt/checkpoint/resume/export and report capabilities. Sandbox adapters provision/execute/upload/download/checkpoint/restore/fork/destroy and report resize support.

Memory has complete retained records, runtime-specific active context, and canonical scientific evidence. Compaction cannot promote a conjecture. Restart briefs retain exact target revisions, assumptions, open obligations, accepted dependencies, failures, and provenance. Cross-model handoff does not assume opaque native continuation portability. Forks bind workspace/context/target/environment lineage and obtain new execution authority.

Independent acceptance retrieves a reviewed target and immutable trusted environment, constructs/exports untrusted candidate source in qualified Linux isolation, compares definitions and statements, audits the transitive axiom closure, and replays exported proofs through the configured kernels. Default permitted axioms: propext, Quot.sound, Classical.choice. Reject sorryAx, extra mathematical axioms, and native-computation trust in the strict tier. Comparator and independent kernels require pinned, validated installation. Never mistake successful Lean compilation, worker-supplied JSON, or regex inspection for proof acceptance. Publication tier requires an independent kernel. Definition holes and semantic changes require review. Timeouts, unsupported environments, conditional results, refutations, and failures have explicit distinct outcomes.

Agents may explore incomplete arguments, numerical calculations, custom tools, and proposed definitions freely inside their workspace. Only the independent acceptance service can issue receipts. A changed target or trust policy creates a new revision; old receipts remain historical and cannot silently satisfy it. Integration rebuilds combined artifacts with consistent dependencies.

## Approved execution order (2026-09-22)

This order prioritizes useful scientific results and measured bottlenecks. It does not renumber waves, reduce their full scopes or exit criteria, or turn an early pilot into wave qualification. Both quantum and classical programs continue in parallel. The end goal remains large, durable, heterogeneous swarms of agents and subagents advancing expert-selected root physics targets through formalization, independently accepted results, autonomous collaboration, and recovery across compaction and failure. Fleet size and learned policies must earn their place by improving useful science.

1. **Prove the small live loop.** Select a small expert-reviewed development subset with exact formal targets, trusted environments, and qualified scoped deployment. Run a bounded live single-agent model-to-independently-accepted-proof trial, then demonstrate retrieval and reuse of an accepted lemma. Record cost, elapsed time, assumptions, receipt provenance, and failures. This pilot need not wait for expert review of all 40 candidates or a production fleet. The pilot still requires selected-target review, independent acceptance, and deployment authority; it does not qualify Waves 0–2 or waive their complete exit criteria.
2. **Recover and account for real work.** In parallel with the small loop, finish the Wave 3 recovery/reconciliation contracts: ambiguous model and VM operations, safe lease adoption, orphan cleanup, and financial settlement after uncertain provider calls. Keep one lifecycle owner through Temporal and the canonical controller; do not add a second top-level controller. Separate research, verifier, control, and reconciliation capacity pools, with bounded I/O and instrumentation. Checkpoints must carry pinned image identity, source changes, artifacts, and enough context to resume exact obligations. Stream practical manifests; full RAM snapshots are optional accelerators, and each branch need not copy all of Mathlib.
3. **Grow to small teams and usable knowledge.** Exercise selected Wave 4 and 5 work with 2–8 agents: delegation and collaboration, robust checkpoints/compaction, and provenance-checked accepted-lemma retrieval. Add one more runtime when it enables a concrete comparison. Keep distinct helper, persistent collaborator, and competing-branch lifecycles; test parent loss and handoff without treating opaque native continuation as portable.
4. **Measure search policies early.** Bring selected Wave 6 evaluation forward: compare sustained single-agent work, independent parallel attempts, and collaborating teams at matched cost and wall time, with a uniform-allocation baseline. Measure valid accepted root results, reuse, duplicated work, review effort, coordination cost, and uncertainty. Decompose mathematics only when the model or evidence supports it; no obligatory proof scaffold. Promote policies only on reproducible matched-budget evidence.
5. **Scale measured work.** Increase active capacity through 8, 32, then 128 workers while tracing bottlenecks and preserving recovery and accounting. Wave 8 still requires its complete operational suite and the unchanged live 72-hour, 128-active-worker qualification.
6. **Expand providers and self-hosting conditionally.** Benchmark one alternative VM provider under the same acceptance, recovery, and accounting contract. Choose Kubernetes, self-hosted isolation, and Ray workloads from measured need. Evaluate existing lifecycle controllers and VM isolation first; custom Firecracker orchestration remains a candidate, not a prerequisite. Retain the self-hosted capability goal and Wave 9's meaningful 1,000-worker qualification.
7. **Add specialized discovery and learning when evidence calls for them.** Prioritize Wave 7 certificates/computation where a concrete formal bottleneck benefits; use Wave 10 learning only after verified, provenance-preserving data and held-out benefit justify promotion. Their full scopes remain on the roadmap, but neither is a prerequisite for early research. Wave 11 open-problem pilots may begin once small teams are reliable, experts have selected precise targets, and existing review/acceptance controls apply. Full sustained campaign qualification still requires durable operation and the scientific exit criteria.

The next reviewable deliverable is a reproducible comparison of one agent and a small team on meaningful physics solves, with independently accepted results, recovery observations, and reconciled cost/time accounting. A large fleet alone is not evidence of useful research.

## Waves and acceptance goals

0. Repository, contracts, dependency locks, two program charters, declaration-level library audit, 40 valid task candidates (20 per program) and 20 altered/invalid cases. Family-separated development/holdout splits. Every item records provenance, reference outcome, and honest expert-review status. Qualified exit requires expert review and a reproducible pinned build.
1. Trusted problem bundles, isolated Comparator acceptance, independent-kernel path, receipts, semantic review, and attack corpus: changed definitions, hidden holes, tainted dependencies, extra axioms, false success files, inconsistent assumptions, and caches. All known attacks fail closed or require review.
2. Runnable single-agent loop with Codex SDK and minimal direct-API baseline; files/shell/retrieval/Lean/artifacts; CLI; optional research skills; traceable configuration. Qualification needs actual accepted results and subsequent lemma reuse in each program.
3. Managed Temporal/PostgreSQL/S3/E2B/AWS deployment, outbox, leases, accounting, external checkpoints, pinned templates, reconnects, backoff and recovery. Qualification requires live fault injection without lost accepted results or uncontrolled duplicate allocations.
4. Claude SDK/OpenHands adapters, nested delegation, mailboxes, orphan recovery, native and portable checkpoints, compaction, handoffs, and sandboxed model-written JavaScript orchestration. No silent model substitution. Qualification requires mixed-runtime research with preserved evidence across failures.
5. Paper/LaTeX/Markdown/PDF ingestion, source spans, reviewed formal targets, hybrid premise and bundle retrieval, version invalidation, conditional knowledge, counterexamples, failures, and readable proof outlines. Qualification requires held-out premise applicability and a source-to-reviewed-target-to-accepted-proof run.
6. Direct, independent, blueprint, recursive, tactic, and mixed-model search policies. Uniform baseline; adaptive candidates; independent seeding; configurable sharing; protected deep attempts; shared-blocker diagnostics and global replanning. Conditional child-to-parent checks; coupled metavariable awareness. Promote only on matched-budget evidence.
7. Symbolic/numerical simulation, reproducible precision/parameter/error metadata, refutation, exact certificate formats and Lean checkers, matrix/polynomial/rational/SOS/interval witnesses, evolutionary candidate search. Numerical evidence never counts as a proof without the configured certificate or formal argument.
8. Private research console, live steering, reviews, source/proof/graph views, role separation, reproducible packages and draft PR preparation, backups, migration/release runbooks. Live 72-hour/128-active-worker qualification; distinguish model, verifier, simulation, and idle work.
9. Sharded coordination, subscriptions, Continue-As-New, fairness, verifier-aware admission, alternate VM providers, self-hosted VM isolation and Kubernetes/Ray workloads, provenance-aware caches and snapshot compatibility. Evaluate existing lifecycle controllers and isolation options before choosing whether a custom Firecracker/KVM host pool is warranted. Live 1,000-worker qualification for meaningful work and recovery.
10. Provenance-preserving verified datasets, learned retrieval/ranking, open-weight supervised policies, experiment-scoped test-time training/RL, curricula and evolutionary discovery. Fixed trusted rewards, holdout isolation, regression and exploitation checks; promote only on independently evaluated improvements with rollback.
11. Expert-selected nearby open lemmas then difficult root problems in both programs; diverse groups and shared foundational work; extend to infinite-dimensional analysis/PDEs/geometric mechanics/field theory as prerequisites permit. Weeks/months of durable campaigns, rigorous assumptions, novelty review and accurate publication of successes and unresolved outcomes.

## Evaluation and operation

Compare runtimes, direct/decomposed/adaptive policies, sharing modes, heterogeneous models, context strategies, retrieval, numerical tools, and learning under equal cost and equal wall time. Track accepted root targets, costs, useful reuse, duplicated work, review effort and uncertainty. Mask target proofs and leaking descendants in discovery benchmarks; literature-assisted work is separate. Never count simulated model activity as live scale.

Inject failures during model requests, source compilation, uploads, receipt commits, parent/child work, snapshots, outbox dispatch, target changes, and migrations. Recheck exact assumptions after compaction. Mutable effects require idempotency and expected revisions. Reconcile ambiguous provider calls rather than promising exactly-once billing.

Production targets: no accepted-artifact loss during ordinary process/worker failure; recovery/requeue within five minutes when capacity is available; new allocation stops immediately on cancellation and worker signalling within 30 seconds; metadata API p95 <2 seconds; console updates within five seconds; disaster RPO <=5 minutes/RTO <=1 hour; clean reconstruction of every public proof.

Small reviewed PRs, conventional commits, protected branches, independent review of acceptance/definitions/credentials/promotion, pinned CI, release notes, ADRs, incident reports and explicit wave status. Retain accepted dependency closures and evidence; caches/snapshots are replaceable. Publication packages include claim, assumptions, proof outline, provenance, receipts, configuration, usage and reproduction instructions. No calendar deadline, cloud credentials, or unrestricted live-spending authorization is implied.
