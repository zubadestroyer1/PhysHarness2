# Failed local workspace recovery

This is an operator procedure for a **failed, zero-charge local Docker `run` or workspace `export`** whose canonical workspace and operation are `reconciliation_required`. It does not recover a generic VM provider, decide an ambiguous provider bill, retry a model call, or establish proof acceptance. The retirement command records an operator attestation of external observations; it cannot itself prove that Docker destroyed the container.

1. Stop admission for the affected attempt and pause or cancel its experiment. Inspect its task, lease, workspace, operation, reservations, and model charges through the issued project operator. Confirm the task is blocked or failed, its original holder/fence has expired or been released, the workspace still names the exact execution ID and uncertain `run` or `export` operation, and every model reservation has settled. Do not start another attempt against this database or workspace.
2. Before destroying the container, copy the needed `/work` files to a private recovery directory using the dedicated Docker socket and **the exact recorded container ID**. Preserve the archive and a SHA-256 digest. Keep proof sources and transcripts private; a recovered file is evidence of what was present, not a verified proof. Record the container identity and diagnostic observations without printing private source in logs.
3. Destroy only that identified container after the archive is secured. Check Docker's response and independently inspect the same dedicated daemon to confirm the exact container is absent. An empty name search or elapsed timeout alone is insufficient. If identity, destruction, or billing remains ambiguous, stop for operator investigation; do not attest absence.
4. With an unbound, project-scoped operator identity, create a private `workspace_recovery_observation` artifact in the same experiment using `HarnessService.create_artifact`. Its `branch_id` and `trusted_input` remain unset/false. Its provenance contains the exact `workspace_id`, `execution_id`, lowercase `archive_sha256`, and `destruction_confirmed: true`, `absence_confirmed: true`; it has no task scope. The content should state the operator's actual observations and archive location without embedding a proof transcript. The artifact's `submitted_by` must be the operator who retires the workspace.
5. Read the workspace's current revision and call `HarnessService.retire_failed_local_workspace(workspace_id, expected_revision, expected_execution_id, evidence_artifact_id, actor, key)` with a fresh idempotency key. The command checks the original task and lease binding, paused/cancelled experiment, local provider, uncertain `run` or `export`, observation artifact, and zero-cost workspace/shared-slot reservations. In one transaction it records the operation as operator-retired, marks the workspace destroyed, settles those two reservations at zero, and marks abandoned running/handed-off sessions and the failed task accordingly. Completed native sessions and accepted verification receipts remain intact. It rejects unexpected native-session states and unsettled model charges. A repeat with the **same key and inputs** returns the original result; a different key is not a replay mechanism.
6. Re-read the canonical records and ledger, then export the attempt and validate artifact hashes. Confirm no active or uncertain reservation remains and that **previously settled model spend is unchanged**. Keep the failed attempt and its archive as an immutable audit trail. Any replacement attempt uses separately prepared campaign/experiment, database, artifact store, and budget; retirement never resets paid usage or authorizes a retry under the failed attempt.

The method is limited to a zero-cost `local_docker` workspace with an uncertain failed `run` or `export`, an expired original lease, and a blocked/failed task. Other workspace commands remain ineligible. It records operator evidence rather than an independent destruction certificate. Recovered Lean files require the normal exact-target verifier and acceptance process before any proof claim.
