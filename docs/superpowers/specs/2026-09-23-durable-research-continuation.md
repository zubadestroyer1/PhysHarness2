Implement the agreed long-horizon architecture into the existing harness: exact scientific memory and retrieval; automatic native compaction; safe successor handoff; delegated, collaborating and competing investigations; independently checked lemma reuse; selective communication; durable execution and one shared resource envelope. Models retain choice of mathematics and collaboration. Root plans and audits; GPT-6 Sol agents implement. The target is usable, fault-aware continuation and collaboration, not a claim that unlimited fleets or mathematical success have been qualified. Existing Temporal/outbox/PostgreSQL architecture remains the distributed controller. The finite local runner uses the same canonical services. No second controller or mandatory binary tree.

## Scientific authority and memory

Preserve existing PortableMemory checkpoint v1 semantics and tests. Add a bounded working-context view assembled from canonical records: exact target/review/environment, assigned task and branch, current relevant evidence, accepted dependency references, pending and failed obligations, and explicit paginated history/inventory. Parent-child scheduling visibility is distinct from sharing private research. Enforce none/verified/ideas sharing; shared free text requires ideas. Models may generate decomposition but no proof method or depth is mandatory.

## Context and continuation contracts

Separate active request context from cumulative tokens, turns, wall-clock and dollar limits. No continuation, compaction, child or branch obtains a new experiment budget. Add typed inline Responses context_management compaction, preserving opaque provider items in native checkpoint storage. Prune only the prefix before the latest valid compaction item after all returned calls have matching outputs and usage is authoritatively settled. Native transcript/audit history remains retained. Do not silently accept malformed compaction or provider usage that exceeds reservations. Requests stay under a configured active-context cap; unsupported provider capability fails loudly.

Provide a runtime safe-boundary hook. It runs after accounting/tool settlement and checkpoint persistence, can produce a typed continuation result, and never interprets arbitrary tool content as controller authority. Continuation is a separate outcome from mathematical or task completion. The controller persists a continuation request and ready checkpoint, releases the task lease and worker capacity, then resumes at a new execution identity. Successor handoff uses portable scientific state and attributed notes; same-runtime continuation can retain its exact native state where safe. Cross-model handoff accepts only configured model choices. Pending or uncertain external operations require reconciliation and must not be repeated automatically.

Handoff and waiting for descendants are durable task lifecycle operations. A parent waiting for a child yields its slot; one-slot experiments cannot deadlock by holding capacity while awaiting queued children. A successor validates target/review/branch/state freshness. Existing tool-operation identifiers remain idempotent; lineage links old/new native sessions. Child failure is an explicit outcome the parent can inspect, not an eternal prerequisite wait.

## Integration and finishing

Keep original record identities and historical receipts. Avoid destructive migrations and unrelated refactors. Add scoped communication/status tools rather than all-to-all transcript sharing. Task ownership uses existing renewable leases and fencing. Temporal activities and the finite runner both understand waiting/continuation; duplicate delivery cannot resume one continuation twice. Histories and loop epochs are bounded through existing Continue-As-New and explicit continuation limits.

Designated proof submission should store the candidate and durably request verification without requiring another model generation just to submit saved bytes. Exploratory drafts remain drafts. At token/dollar/time stop, retain checkpoints and finish already queued verification within its separate deadline. Report the precise exhausted resource and task outcomes; do not label execution completion proof acceptance. Model reservations, uncertain costs and worker capacity remain reconcilable after failures.
