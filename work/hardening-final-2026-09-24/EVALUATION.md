# Evaluation registered before live calls

This is an engineering and difficulty-calibration pilot, not an open-problem result or a matched statistical comparison of one versus many agents. The target is an assistant-authored known-type stability result. The single-agent run and the cooperative run have different budget ceilings and must not be ranked as an equal-budget comparison.

Record every attempt, including failures and any retired replacement. Report exact target/environment/receipt bindings; valid root proofs and useful independently accepted intermediate results; time to first submitted and first verified proof; total duration; unsolved obligations at termination; conservative ledger spending, native token usage and separately labeled price-based estimates. A supervisor's completed status is not a proof-success verdict.

Report agents actually started, optional delegation, helper execution while roots remain active, parent waits, and completed or unresolved continuation chains. Count sent, delivered and acknowledged messages separately. Compare communication times to candidate submissions. Delivery before submission is an opportunity for contribution, not evidence that the idea improved the proof; report actual cited or formally reused findings when traceable. Do not infer benefit from agent count alone.

Distinguish provider-produced compaction items, actual pruning of active input, fresh sessions, same-runtime handoff, portable handoff and deterministic recovery fixtures. Zero compactions in a live run means long-horizon provider behavior was not exercised, regardless of successful mock tests. No artificial history padding or lowered research context threshold is used to make the target appear difficult.

A much slower successful proof, or substantial unresolved mathematical work at the budget ceiling, establishes that the target is more demanding for this configuration. Fast completion is reported as missing the intended difficulty; an infrastructure failure is not evidence of mathematical difficulty. An unsolved finite-budget run is not evidence of impossibility.

Preserve independent verifier controls, host-test output, VM capacity/restore/cancellation observations, OOM diagnostics, export hash checks, and final resource reconciliation. The local four-worker test cannot qualify cloud durability, 128-worker endurance, or thousand-worker scaling.
