# Independent final integration audit

Read-only review of the integrated continuation, scientific memory, workspace, Temporal, public API and accounting changes against `docs/superpowers/specs/2026-09-23-durable-research-continuation.md`. This is a code-path audit; local infrastructure and live scientific qualification belong to the root evidence ledger. No private state, credentials, model logs or paid calls were inspected.

## Findings and resolution

1. **High — Native checkpoint content was reachable through generic agent API routes; resolved in code and API test.** The generic collection and detail routes include `sessions` and `artifacts` (`src/physharness/api.py:301-320`); a session row exposes `checkpoint_artifact_id` (`src/physharness/orchestration/research_worker.py:122-136`), and artifact content is exposed at `src/physharness/api.py:368-370`. The original `service._in_scope` granted same-branch access before checking private kinds. The current `src/physharness/service.py:229-234` denies native sessions/checkpoints/archives/runtime events before owner access; lines 252-253 still deny cross-branch portable checkpoints. Initial blanket denial also blocked own portable checkpoints: `.venv/bin/pytest -q tests/test_handoff_notes.py` produced 2 failures. After splitting portable from native, the same command produced **4 passed**. `tests/test_memory_api.py:104-146` directly checks that a same-branch agent cannot list, inspect or read content of a native checkpoint, while an operator can inspect its metadata; it passed in the 48-test focused run below.

2. **High — A completed native result could be stranded after process death; resolved in code and focused tests.** `src/physharness/execution/responses.py:402-418` persists a terminal checkpoint before the executor creates output and finishes the task. The executor now recognizes a settled `completed` checkpoint (`src/physharness/orchestration/research_worker.py:633-650`), reconstructs exact output from the saved native response with `ResponsesRuntime.completed_result` (`src/physharness/execution/responses.py:593-673`), and finishes under a new fence (`src/physharness/orchestration/research_worker.py:874-901`). `tests/test_controller_continuation.py:332-410` covers a persisted completed checkpoint, expired source lease, leaked one-slot reservation and provider-forbidden recovery; it asserts one native session and exact saved output. `.venv/bin/pytest -q tests/test_controller_continuation.py tests/test_execution_context.py` produced **39 passed**.

3. **High — Temporal continuation delivery after activity death has integrated real-engine coverage, with bounded scope.** The continuation `task.queued` outbox event is accepted as a duplicate while the original workflow is running (`src/physharness/orchestration/temporal_delivery.py:54-60`) without a new start or signal. `TaskWorkflow` now retries an activity up to three times (`src/physharness/orchestration/workflows.py:45-51`), and the worker maps an active source lease to a five-second `waiting` cycle (`src/physharness/worker.py:82-124`). `tests/test_temporal_integration.py:235-315` runs the canonical executor under a real local Temporal engine, loses the first activity result after committed handoff, and checks two native session IDs and exactly two provider generations. `tests/test_controller_continuation.py:25-99` injects failure after ticket issue before final slot settlement and checks the one-slot successor. Root's opt-in command `PHYSHARNESS_RUN_TEMPORAL_TESTS=1 pytest tests/test_temporal_integration.py -q` produced **5 passed in 21.82s** (`work/long-horizon-2026-09-23/temporal-final.log`). These tests cover complementary windows; neither kills an operating system process during an in-flight provider request. My default invocation without opt-in skipped, as designed.
