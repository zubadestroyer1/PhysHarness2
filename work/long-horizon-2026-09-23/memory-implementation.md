# Bounded scientific working context implementation

Implemented in `src/physharness/memory.py` without changing `portable-context.v1` checkpoint and restore behavior.

- `PortableMemory.working_context(branch_id, actor, *, task_id=None, max_bytes=65536, page_size=10, selected_ids=None)` issues `physharness.working-context.v1`. It carries the exact target, review, branch binding, and current task, plus bounded index references for open tasks, open claims, failed attempts, and public artifacts. Each index reports completion and a cursor. It does not claim all history is present. Selected references retain canonical hashes and status checks. The target/current-task core fails explicitly if it cannot fit.
- `PortableMemory.read_record(branch_id, actor, *, kind, identifier, max_bytes=65536)` returns authorized exact metadata and a verified reference, with a byte envelope. Artifact content remains retrieved through the existing artifact tool.
- `PortableMemory.read_artifact_chunk(branch_id, actor, *, artifact_id, offset=0, max_bytes=16384)` returns byte-exact base64 chunks, offsets, total length, and a hash-checked reference. Native/private artifacts and other branches remain excluded.
- `PortableMemory.index_page(branch_id, actor, *, index, limit=50, after=None)` pages a precise branch-local status filter. The working-context manifest names the index, record kind, branch, filter, and cursor. The indices now include accepted claims; forged verified labels fail canonical acceptance validation.
- `PortableMemory.research_graph_page(branch_id, actor, *, limit=50, after=None)` pages branch-visible nodes and explicit field-backed links: task dependency/delegation/branch assignment, claim evidence/receipt, verification target, artifact task origin, source artifact, program ancestry/source, and branch ancestry. Links to hidden/private records are omitted. It makes no proof inference.
- The graph page also accepts `max_bytes=65536` and `max_edges=100`. It returns a cursor before any node that would overflow, or raises `GRAPH_NODE_TOO_LARGE` when one node alone cannot fit; callers can then read that exact record. Invisible scans advance the cursor without disclosing hidden records.
- Existing `history_page` remains the keyset retrieval interface for exact older references; the controller will expose it as a worker tool.
- `history_page` and `index_page` now enforce a 64 KiB default response envelope; callers can reduce the page limit if a record-rich page exceeds it. An individual oversized reference fails explicitly.

`checkpoint_research_notes(branch_id, actor, key, *, approach, unresolved_obligations, summary=None, evidence_ids=None, task_id=None, holder=None, fence=None, max_bytes=8192)` is an additive `research-notes.v1` checkpoint. It stores exact hashes for the current target, review, and environment, optionally binds the current task and selected canonical evidence, and labels the scientist's approach, summary, and unresolved items as attributed, unverified notes. It records obligation counts and streaming fingerprints of IDs/revisions, with an explicit incomplete-history marker and index retrieval hint. It does not embed the full `_core`, so large histories do not consume the notes envelope. Issuance verifies that the corresponding handoff response fits its envelope. Existing `portable-context.v1` format, restore, and tests remain unchanged.

`handoff_notes(branch_id, actor, *, task_id=None, max_bytes=8192)` selects the latest issued notes or v1 portable checkpoint on that branch/task. It validates lineage or issued-notes integrity and rechecks the exact target/review/environment. When the current task, obligations, or selected evidence changed, it marks the source stale, retains attributed unverified text, and excludes changed evidence references. It does not promote notes to proof or restore stale statuses. Branch scope and private-artifact exclusions still apply. The controller binds the selected checkpoint ID and SHA-256 to a successor continuation ticket and includes notes in the fresh prompt and compaction anchor.

`tests/test_working_context.py` covers large task and failed-receipt histories, bounded initial context with reserved manifests, exact target and task, precise index continuation, scoped selected reads, byte-exact chunk reconstruction, private/native exclusions, forged verified status, stale target/review binding, graph fanout rejection, and invisible-page continuation. Existing `test_memory.py` and `test_memory_api.py` pass unchanged.
