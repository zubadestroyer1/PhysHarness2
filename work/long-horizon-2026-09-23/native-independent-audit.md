# Independent native Responses audit (2026-09-23)

Read-only review of `execution/responses.py`, `execution/storage.py`, `execution/types.py`, `execution/parameters.py`, the canonical runtime store in `orchestration/research_worker.py`, and their focused tests. No native code was edited, and no provider or VM was called. `.venv/bin/pytest -q tests/test_execution_context.py tests/test_execution_responses.py tests/test_controller_continuation.py` passed: 29 tests after the runtime author fixed the issue below.

## Material finding resolved during review

The first version of `ResponsesRuntime._advance_active_input` archived only `responses` and `tool_results`, then replaced `state['input']` with a suffix. The discarded prefix contained prior user prompts and ordered `function_call_output` items, so the hash proved stored content but not complete native history. The runtime author added the discarded `input_prefix` to each immutable archive before pruning (`responses.py:503-518`). Concatenating archived prefixes in order with current input now reconstructs the ordered input stream.

The updated two-compaction test checks reconstructed item types and prompts (`tests/test_execution_context.py:91-157`). A stronger qualification test should compare every reconstructed item to a captured pre-prune stream, including distinct prompts and tool-output payloads, and verify a corrupt or missing archive fails before a resumed request. The current test establishes the essential ordering but uses the same prompt for each anchor.

## Other boundary observations

- **Tool order is handled deliberately.** After usage settlement, the runtime executes every function call before pruning. When a function call precedes the latest compaction item but its output follows it, `crossing_calls` moves the keep point back to that call. The test covers this ordering (`responses.py:373-491`; `tests/test_execution_context.py:148-176`). Duplicate tool call IDs search prior archives and reuse the recorded result after checking argument identity (`responses.py:392-417`; `tests/test_execution_context.py:239-267`). The archive-prefix fix should keep these behaviors.
- **A terminal response with a compaction item is not pruned.** The no-call path returns before `_advance_active_input` (`responses.py:351-373`). Its full state remains in the terminal checkpoint, so this is not loss, but archive count and compacted-size behavior differ from a tool-call response. If terminal checkpoints are expected to stay small, process a valid compaction before returning or document this boundary.
- **Accounting is mostly ordered safely.** The runtime persists the provider response and usage before clearing `pending_operation`; the controller settles actual usage on the `usage` event before another request (`responses.py:306-331`; `research_worker.py:590-619`). Missing usage or failed settlement retains a pending operation and prevents automatic resume. The experiment ledger charges all successor sessions. The controller's pending reservation fix is present at review time (`research_worker.py:596-610`). Provider-reported actual tokens/cost can exceed the estimated reservation: `settle_resources` records actual spend without enforcing the preflight cap (`service.py:849-892`). This is truthful accounting, but the envelope can be exceeded after an unexpectedly large provider bill; record this as an external overage and stop further work rather than claiming a strict post-fact cap.
- **Handoff is terminal only after a clean tool boundary.** The hook receives a checkpoint after tool outputs and compaction, and `pending_operation` is clear. A `handed_off` source is explicitly rejected by both `resume` and `continue_session` (`responses.py:419-450, 519-525`). The controller binds the exact source checkpoint digest, task, model, target and review, requires no active/uncertain model reservation, and creates a new session (`continuation.py:125-268`; `research_worker.py:485-537, 795-815`). A process crash after persisting `handed_off` but before issuing the continuation leaves a terminal source with no ready successor and requires reconciliation; it must not be replayed automatically.
- **The context anchor is renewed from canonical science.** `context_anchor` checks experiment activity, lease fence and target/review identity, then serializes a fresh bounded `PortableMemory.working_context` before the next request (`research_worker.py:721-740`; `responses.py:469-494`). A stale anchor stops before another paid generation in the focused test. There is a small separate-transaction interval between identity check and working-context read; the working-context method rechecks target digest and review consistency, but exact review or target revision binding should be tested if those records can change in place.
- **Archive storage has integrity checks but finite artifact capacity.** SQLite archives have a `(session_id,id)` key and content digest validation (`storage.py:46-66`). Canonical archives are private artifacts keyed by task/session/digest and rehashed on load (`research_worker.py:141-185`). Each canonical artifact uses `ArtifactCreate.content` capped at five million characters (`domain.py:122-125`); a very large unpruned native checkpoint or archive can fail before compaction can help. This fails closed and preserves the last saved state, but it limits long sessions. Add a preflight size error with remediation or chunked archives before claiming support for larger native histories. The `archives` ID list itself grows linearly with compaction count; it is small in the 20-cycle test but not bounded independently.

No immediate correctness blocker remains in the paths reviewed. The remaining points are defined recovery or capacity limits and should appear in the qualification notes unless changed and tested.
