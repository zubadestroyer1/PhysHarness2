# Fresh two-target pilot operations helper

`pilot_ops.py` provides five importable operations without a model or VM side effect during import, preparation, or status reads:

1. `import_reviewed_targets(source_db, destination_db, manifest_path, project_id=...)` opens the caller-supplied source SQLite database read-only. It fetches only the two exact problem IDs in `TARGETS` plus their referenced campaign and review records. It verifies the target/review/campaign binding, preserves canonical IDs, revisions, payloads and provenance, and writes a SHA-256 manifest. It refuses an existing destination or manifest. No old experiment, artifact, claim, verification, task, session, or proof bytes are copied.
2. `isolated_service(destination_db, artifacts_dir, verifier=...)` opens the new authority; the caller supplies its configured independent verifier. The artifact directory must be a fresh isolated location chosen by the operator.
3. `prepare_attempt(service, operator, target=..., attempt=..., model=..., max_concurrency=2, compact_threshold=8192)` idempotently creates one experiment, branch and root task. **It starts the experiment clock**, so call it immediately before the intended live attempt, after operator configuration and verifier readiness. The model is supplied by the operator; prices are never hardcoded. Each attempt has a $25 shared cost ceiling, 4 million shared tokens, at most two concurrent workers by default, a 7200-second experiment runtime, a 128,000-token active context, 4 million cumulative tokens and 128 turns per session, 16,384 output tokens, and a 3600-second session timeout. The 8192 compaction threshold is intentionally low for code-path qualification and can be set explicitly up to 111,616. The branch and task label the problem a known reviewed target. `sharing='verified'` permits the second attempt to retrieve an accepted first result through the existing exact-binding knowledge service if such a result actually exists.
4. `status(service, operator, descriptor)` returns only IDs, task/receipt states, ledger, and counts of compactions, handed-off sessions and delegated tasks. These counts can be zero; they do not imply mathematical performance. It never returns proof text, model context or credentials.
5. `run_attempt(service, operator, descriptor, prices=..., environment=..., workspace_factory=...)` runs existing preflight, then the live `ResearchTeamRunner` with a 7200-second finite manifest, 64 task and verification limits, and shared descendant scheduling. The caller supplies current prices, environment, verifier and workspace policy. A blocked preflight returns only blocker codes. A terminal root task returns `already_terminal`; a prior session without an issued continuation returns `RECOVERY_RECONCILIATION_REQUIRED`, avoiding a duplicate paid request. The worker's canonical task/session guards provide the final lease and replay boundary. `export_attempt(...)` writes the existing full reproduction export to a new mode-0600 file and returns only its hash and path.

For use, root should pass its private source path, a new database path, an empty artifacts directory, an operator identity in the same project, the configured verifier, the exact selected Responses model configuration, and recorded prices. The helper does not read a default `.state` path, an auth file, a key, or a model price. Root can import the module by filesystem path or place its parent directory on `sys.path`; no command-line arguments or environment values are echoed by this module.

The pilot is an engineering qualification of isolation, compaction, handoff, delegation, accounting and recovery paths. A valid run report may still show zero compactions or helpers, and any mathematical success on these known problems must be reported separately from those code-path observations. A further fresh target would be needed for novelty evidence.

Synthetic tests in `tests/test_pilot_ops.py` check strict source allowlisting, exact imported hashes, rejection of tampered review and foreign project, nonempty destination refusal, idempotent setup and changed-input conflict, resource envelope and compaction settings, redacted status, export mode and hash, and preflight blocking with no session created. No private pilot database, credential or provider was used.
