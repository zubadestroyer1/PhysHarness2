# Native runtime implementation report

Implemented in `execution/parameters.py`, `types.py`, `responses.py`, and `storage.py`, with tests in `tests/test_execution_context.py`. No private credentials, live model calls, or VM operations were used.

- OpenAI SDK 2.54 inline `context_management=[{"type":"compaction","compact_threshold":N}]` is now strictly validated. It requires finite `RuntimeLimits.max_context_tokens`; the threshold must leave configured output room. Active input plus output room is checked separately from cumulative charged-token limits.
- Generation reservation uses the active context cap as conservative **input headroom** when compaction is enabled. This is not cumulative usage or a provider billing guarantee. Actual provider usage is saved, emitted and settled before an over-reservation violation stops further generation. A failed reservation hook clears the pending generation because no provider request has been sent.
- Compaction waits for completed response usage accounting and all function-call outputs. It keeps the latest opaque compaction item, the entire provider response group when a call/output pair crosses the compaction boundary (including preceding encrypted reasoning), and a refreshed scientific context anchor. `context_anchor` is an optional async callback; absent one, the exact initial prompt is re-anchored. Controller callbacks can reject stale target/review state before another paid request.
- Every compaction archives the exact discarded ordered input prefix, full response segment (including encrypted reasoning/compaction content), and tool-result idempotency cache in an immutable digest-addressed store. The active checkpoint keeps archive references and later active input; archived duplicate call results are reused rather than redispatched. SQLite and canonical stores implement `archive`/`load_archive` (canonical implementation is owned by the controller agent).
- `boundary_hook(checkpoint)` runs only after a clean post-tool checkpoint. A validated `{reason}` yields `RuntimeResult.continuation={reason,source_session_id,source_checkpoint_digest}` with `status="handed_off"`, empty output text and no successful output artifact. `resume` and `continue_session` cannot revive that source session.
- `native_state.settled_boundary` is true only before the first generation and after all output/tool/compaction state is durably saved. It is false while a returned response still has unprocessed effects. Interrupted checkpoints with a missing or false marker cannot resume even when `pending_operation` was cleared after usage settlement.
- A persisted `running` checkpoint from a dead process can be explicitly adopted as `ready` only at that settled boundary, with no pending model/tool operation and no active in-process task. An `uncertain` checkpoint still requires reconciliation.
- A completed response containing only a compaction item is archived and re-anchored, then the loop continues within the existing turn and budget limits. A completed response with no text, calls or compaction remains `MODEL_OUTPUT_MISSING`.
- `ResponsesRuntime.completed_result(checkpoint)` is a pure static recovery method for a crash after native completion but before controller finalization. It verifies checkpoint integrity, completed/settled status, no pending model/tool effects, final response identity/model/status/usage and exact input/output placement, then reconstructs SDK-equivalent concatenated output text, native items, and the original output artifact digest/provenance. It never invokes a provider or store.
- When active-input preflight exceeds the context cap after at least one settled turn, an opted-in `boundary_hook` sees durable `context_pressure` metadata and may yield a fresh-session handoff before another generation. A missing hook, refused handoff, or oversized zero-progress initial prompt still raises `CONTEXT_LIMIT`.

Verification: focused execution/context/parameter tests **75 passed** after completed-result and context-pressure recovery; `ruff check` and `git diff --check` passed. A prior broad non-integration run, before the final native changes and after concurrent controller/memory fixes, had **850 passed, 1 skipped, 3 deselected**. Focused tests exercise repeated compactions, encrypted content retention, exact history reconstruction with distinct anchors and tool results, duplicate call replay, crossing call/output pairs with preceding encrypted reasoning, malformed compaction, context caps, conservative reservation and overrun reporting, failed pre-dispatch reservation, compaction-only continuation, stale anchor, unsettled post-usage tool-call interruption, safe running-checkpoint adoption, exact completed-result reconstruction and corruption rejection, and context-pressure handoff with zero-progress safeguards.

Remaining integration note: the controller must pass a bounded authoritative `context_anchor` that verifies target/review freshness. Conservative context-cap reservation may deny a request under a tight experiment envelope even when actual input usage would be lower; this intentionally favors budget safety. Provider inline-compaction billing beyond the finite context cap is not assumed impossible: the authoritative overrun is recorded and execution stops.
