# Model reservation contention and worker preflight

The worker now distinguishes a temporary full reservation from spent-budget exhaustion. On `BUDGET_EXCEEDED`, it reads the current ledger. If `max_cost - spent` covers the requested reservation, a confirmed outstanding hold can settle while the worker waits in cancelable one-second intervals and retries the atomic reservation with a fresh key. The enclosing runtime timeout and experiment deadline still bound work; no model call is sent before reservation succeeds. An uncertain hold returns `BUDGET_RECONCILIATION_REQUIRED`; a truly insufficient balance returns `BUDGET_EXCEEDED` with required and available dollars. No output-token cap was changed, so a configured 256K/64K request still has a $1.28 conservative reservation floor at the planned ceiling prices.

When settlement reports an overrun, the worker records the settled reservation, then stops with `BUDGET_RECONCILIATION_REQUIRED`. Direct formal worker dispatch now consumes structured workbench preflight blockers. The daemon-dedication check applies at initial launch; direct worker dispatch permits a running verifier but still blocks on capacity, capacity-policy, memory, and any future blocked check. An already active workspace owned by a recovering task may be conservatively counted against availability; this path needs an exact identity-aware preflight if exercised.
