# Docker workbench capacity implementation

`LocalDockerWorkspaceProvider` now accepts `max_active_workspaces` as an exact integer in `1..100`, with default `1`. Admission counts running containers bearing `physharness.workbench=true` under a host-wide `/tmp` flock keyed by the canonical dedicated socket path. This lock is independent of `TMPDIR`; the in-process asyncio lock uses the same key. Each launched container carries its configured capacity as a Docker label. A provider encountering an active container with a different capacity fails closed with `PROVIDER_POLICY_MISMATCH`, so concurrent configurations using that socket cannot silently oversubscribe. Legacy unlabeled active workbenches occupy the default single slot and block higher capacities.

Names now include a fresh UUID even for a journal workspace ID, preventing a failed launch's cleanup from removing a different provider's container. The stable `physharness.workspace=<journal workspace ID>` label permits daemon listing by journal ID when launch succeeded but the response was lost; no automatic orphan reconciliation is added here. Concurrent `create()` calls on one provider return `OPERATION_CONFLICT` for the second call. Per-container `--memory 2g`, `--cpus 2`, and isolation flags remain unchanged. `probe_capacity()` reads the daemon listing and reports configured capacity, active count, available slots, policy conflict, and per-workspace resource limits without reserving or launching anything.

Validation: `PYTHONPATH=src .venv/bin/pytest -q tests/test_worker_preflight_checks.py tests/test_local_docker_workbench.py tests/test_research_budget_wait.py tests/test_joined_delegation.py tests/test_research_loop_integration.py tests/test_workbench_capacity_broker.py tests/test_execution_providers.py` → 58 passed. Tests include parallel create with capacity two, a rejected third, conflicting configuration, cross-process lock contention under a different `TMPDIR`, cancellation cleanup preserving another owner, same-journal failed launch cleanup, malformed capacity values, two-provider command overlap, and same-provider command serialization. Red tests for the new constructor, concurrent same-provider conflict, command overlap, and legacy empty-label parsing were observed before implementation.

Tradeoffs and limits: the stable file lock coordinates processes on one host using the same dedicated Unix socket (including symlink aliases). Separate socket proxies to one Docker daemon on different hosts would need a daemon-managed admission mechanism. The read-only probe is an observation, not a reservation; admission rechecks under the lock. The real local Docker qualification in `worker-qualification.json` admitted two workers, rejected a third, ran both Lean/math commands concurrently with the verifier, observed zero worker OOM events, and removed all labeled workbenches. A process-exit simulation left an explicitly uncertain container discoverable by its journal workspace label; the script then removed that exact container and verified zero remained. This demonstrates an operator reconciliation route, not automatic recovery. The verifier report is engineering evidence only (`production_qualified=false`).
