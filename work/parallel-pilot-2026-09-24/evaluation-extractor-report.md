# Read-only pilot evaluation extractor

`evaluate_pilot.py` reads the configured canonical SQLite database using `mode=ro`, `PRAGMA query_only=ON`, and one read transaction. It verifies SHA256 for immutable artifact bytes before reading private runtime event/checkpoint/archive content. It never writes the scientific database, calls a tool/model/VM, or exports proof source, prompts, message bodies, or raw native contexts.

Use distinct evolving snapshots while experiments run:

```sh
python3 work/parallel-pilot-2026-09-24/evaluate_pilot.py --config .state/parallel-pilot-2026-09-24/config.json --mode snapshot
```

Snapshots go to `work/parallel-pilot-2026-09-24/snapshots/<timestamp>.json`. After all four private arm results exist and canonical work has settled, use `--mode final` to atomically write `work/parallel-pilot-2026-09-24/output.json`. Final mode refuses active workers, holds, open model reservations, nonterminal tasks, queued verifications, unsettled native responses, or unfinished supervisor results. The script fails loudly on missing canonical budget, problem, candidate artifact, artifact digest, model usage, or probe state. Fields that cannot be inferred are `null` with a reason, rather than zero.

Each arm reports current ledger ceiling and held cost, unique paid response IDs and cumulative input/output tokens, calculated bill *estimate*, not an actual bill, from cache-read/write usage when all details exist, exact first verified event time and seconds after experiment start, cost ceiling at first receipt, and calculated bill estimate at first receipt when command/settlement correlations and cache details are complete. Receipt entries include status, assurance, axiom lists, checker versions, claim and candidate/target hashes, and explicit binding checks against rehashed candidate bytes. Runtime metrics deduplicate response IDs across accumulated checkpoints and archives, count 64K cap hits by `incomplete_details.reason`, active compactions, provider compaction items, completed tool calls, retrieval calls, safe rejected tool codes/operation IDs and execution failure codes. Coordination metrics count actual `delegated_from_task_id`/`reply_to_parent_task_id` child tasks, issued handoffs, recruits inferred from delegated tasks, message records, discussion posts and deliveries. Root and child task outcomes are separate. Duration is measured from canonical experiment start to the last task.completed event, not later operator pause time. Aggregate output includes the reconciled $0.006090 probe upper charge and checks spent plus outstanding holds plus probe against $100. These are descriptive observations, not causal attribution.

Read-only validation against the live database (no output file written) found four configured arms, correctly deduplicated 47 quantum-independent paid responses at the inspection instant, three verified receipts, and one detached child task that the live status helper's `parent_task_id` metric missed. Its first verified receipt was at 07:55:42 UTC with $0.560625 settled ceiling and $0.181052 cache-aware bill estimate at that event. Continued spending after it corresponded to the two roots and detached child completing at 07:55:48, 07:56:32 and 07:58:19, with later verified receipts. The rejected `RETURN_RESULT_SCOPE` tool call was from that detached child (no `reply_to_parent_task_id`), which is expected scope enforcement; `SHARING_POLICY` and `UNSAFE_PATH` are also tool rejections, not infrastructure failures.

Synthetic tests cover native response deduplication, cache-read/write cost, safe rejection counts, retrieval calls, duplicate settlement replay, detached child classification, event-time duration, and candidate byte tampering. `PYTHONPATH=src .venv/bin/pytest -q tests/test_parallel_evaluate_pilot.py` passed 4 tests. Ruff check passed. No live launcher modification or paid call occurred.
