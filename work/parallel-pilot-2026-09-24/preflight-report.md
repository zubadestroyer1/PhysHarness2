# Capacity-aware launch preflight

Implemented `worker_max_active_workspaces` (default 1, validated 1–100, rejects boolean) and passed it through configured factory construction and restoration. `run-team` now sends its actual requested concurrency into `run_preflight`; `check-run --concurrency` previews the same check. Local Docker preflight checks the pinned image, active workbench count and capacity policy labels, then reads Docker daemon memory, CPU capacity, and total running containers. It blocks unrelated containers on the dedicated daemon. It returns machine-readable capacity, memory, and CPU checks. Capacity or memory failures become coded blockers before queueing or model calls. CPU oversubscription, including active workbenches and verifier CPUs, is reported as a warning.

Memory requirement is 2 GiB per requested worker plus 8 GiB for the independent verifier and 2 GiB headroom. `estimated_unallocated_memory_bytes` subtracts 2 GiB for each observed active workbench from Docker's daemon `MemTotal`. Docker does not expose live free memory in `docker info`, so this is a reservation estimate, not a live pressure reading. Docker info errors block with `PROVIDER_UNAVAILABLE`. E2B preflight is called with its existing no-argument interface. The capacity checks only apply to the formal-research profile.

The companion settlement guard records actual over-reserve charges in the ledger, marks the experiment `budget_reconciliation_required`, emits `resources.overrun`, and rejects new reservations with `BUDGET_RECONCILIATION_REQUIRED`. It keeps settled usage evidence and idempotent replay. This addresses the audited risk of silently continuing after a provider charge exceeds its hold.

No provider credentials, VM starts, or model calls were used.

Limitation: preflight is a point-in-time check. The provider's allocation capacity enforcement remains authoritative when concurrent launches race after preflight. The daemon-memory estimate assumes each active workbench reserves its 2 GiB limit, and separate host processes can consume memory after this check.
