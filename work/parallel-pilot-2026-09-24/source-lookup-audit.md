# Source lookup audit after four live arms

All ten `lookup_library_source` calls in the nine final native sessions returned `UNSAFE_PATH`. The mismatch is in the tool contract, not evidence of a dangerous path attempt. `WorkspaceTools.search_library` in `src/physharness/orchestration/workspace_tools.py` walks `/opt/sources/{physlib,mathlib}` and returns `os.path.join(folder, name)` as each hit's `path`; all 72 hits from 15 recorded searches were absolute paths under those roots. `WorkspaceTools.lookup_library_source` in the same file accepts only `.lean` paths beginning `physlib/` or `mathlib/`, then prepends `/opt/sources/`. Six rejected calls passed an exact `path` from a preceding search in the same session. The other four used suffixes of search hits but omitted the required root: three had the shape `QuantumInfo/States/<file>.lean`, and one `Mathlib/Analysis/<file>.lean`. Thus the remaining four reflect a model's plausible attempt to shorten a search path, while the six exact copy failures prove the tool output itself is incompatible with its paired lookup input.

Highest-impact fix for the next version: make the search hit's primary `path` the canonical lookup argument, such as `physlib/QuantumInfo/States/<file>.lean` or `mathlib/Mathlib/Analysis/<file>.lean`. Derive it only from the two pinned roots and preserve the bounded relative-path validation in lookup. If absolute provenance is needed, expose it under a distinct `guest_path`; also return canonical `path` from successful lookup so a subsequent call remains round-trippable. Update both tool descriptions to say that search `hits[].path` is accepted directly by lookup. Do not broaden lookup to arbitrary absolute paths or infer a root from a bare module path.

Regression tests should run search and pass an actual hit's `path` unchanged to lookup for one Physlib and one Mathlib file; verify the returned hash/text and path, and separately reject absolute paths outside the roots, `..`, empty components, and non-`.lean` files. A contract test using a fake workbench can catch output-shape drift without a VM; a pinned-image opt-in test can verify the real source tree. No production code or frozen qualification artifact was changed in this audit.

Resource cross-check: all four live result files report `completed` with nine completed task outcomes, nine independently checked verification receipts, zero uncertain operations, and no capacity failure code. All 142 workspace-operation records are `completed` (including nine provisions, nine exports, nine destroys); no operation error code is recorded. The nine verifier receipts report no confirmed OOM and all container cleanups as `removed`. Frozen `worker-qualification.json` reports two overlapping Lean/math commands with worker OOM deltas of zero, a refused third slot, successful verifier cases, and zero active workbenches after cleanup. These observations do not establish behavior beyond this one pilot.
