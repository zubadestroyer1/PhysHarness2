# Independent ResearchNetwork audit

Scope: read-only review of Task A's frozen discussion implementation and adjacent existing message creation, using the approved specification and implementation plan. The only workspace edit for this audit is this report. No model, VM, credential, commit, or push action was used.

## Confirmed blocker

**P1 — An unreadable attachment can permanently block a branch inbox.** `send_message` validates attachments with the sender's principal only (`src/physharness/collaboration.py:505-510`), whereas `discussion_updates` reads the message and every attachment as the recipient (`src/physharness/discussion.py:78-88`, `:589-612`). With `sharing="ideas"`, alpha can create a `checkpoint` artifact, which alpha can read but beta cannot (`src/physharness/service.py:323-355`). Alpha can then send beta an addressed message with that artifact ID. The send commits, but beta's first and every later `discussion_updates` call raises `DELIVERY_INACCESSIBLE`; the ordered event cursor cannot pass it. This violates the durable bounded delivery contract and blocks later valid updates too. The same recipient-readability rule should be enforced when `finish_task` generates a child-return message with copied `artifact_ids` (`src/physharness/collaboration.py:330-353`), or message attachment handling should provide an explicit bounded inaccessible-reference outcome that advances safely without leaking content. A sender-side check alone does not establish recipient access.

Reproduced against the current code with a temporary SQLite database and public service calls. `ArtifactCreate(kind="checkpoint")` by alpha succeeded; `get_record` confirmed alpha could read it; `send_message(alpha, beta, ..., [checkpoint_id])` succeeded; two consecutive `discussion_updates(experiment_id, beta)` calls both returned `DELIVERY_INACCESSIBLE`. A `native_checkpoint` attachment is already rejected at send time because even alpha's generic record read is denied; the reproducible failing kind is `checkpoint`.

The generic message record and export use `_in_scope` without rechecking message attachment IDs (`service.py:329-355`, `:1347-1357`), so the accepted message can expose the private checkpoint identifier through those surfaces even while typed message retrieval and inbox delivery fail. Creation-time recipient checks prevent new occurrences; already persisted invalid messages need the explicit settlement path below.

**P1 — Scope revocation has no durable settlement path, so a formerly shared event blocks all later updates.** The reader cannot receive or acknowledge a now-inaccessible pending delivery (`discussion.py:523-539`, `:641-673`). For an event not yet delivered, `discussion_updates` retries the first now-inaccessible post on every poll (`discussion.py:589-612`), so it never reaches later eligible events. A privacy-preserving, explicit quarantine/skip outcome should record the event ID and reason and advance only the affected reader's cursor with auditable authority; it must not reveal the revoked excerpt or silently omit it. Reproduced using public services and a policy change in a temporary SQLite database: beta subscribed to alpha's topic while sharing was `ideas`; alpha posted; the experiment sharing policy changed to `none`; beta sent itself a valid addressed message. Two consecutive beta polls both raised `DELIVERY_INACCESSIBLE`, and the later valid self-message was never delivered. The same issue applies to policy revocation after a batch is pending.

If a pending delivery returns a changed withdrawal notice under the same ID, it appends and saves that notice before ack, while identical redelivery remains deduplicated (`execution/responses.py:213-242`). The runtime factory hook now forwards updates when its signature accepts `**kwargs` (`orchestration/research_worker.py:1228-1235`). The new same-ID regression passed.

Focused verification actually run: `test_direct_message_rejects_attachment_recipient_cannot_read`, `test_auto_return_omits_private_attachment_without_poisoning_parent`, and `test_changed_withdrawal_for_same_delivery_is_persisted_before_ack`: **3 passed in 0.45s**. ## Withdrawal implementation re-audit

The second original P1 is **resolved for agent inboxes**. An inaccessible, otherwise well-formed source becomes a fixed withdrawal item with no source ID or excerpt, while the canonical audit stores source ID, reader, delivery and sequence (`discussion.py:140-149`, `:152-250`, `:693-752`). Pending batches are sanitized durably before redelivery. A direct ack after revocation returns `DELIVERY_CHANGED` without advancing, so the caller must reread and checkpoint the notice (`discussion.py:760-845`). The Responses hook detects that error, rereads once, saves the changed payload under the same delivery ID, then acks (`execution/responses.py:230-251`). Tests cover pending and undelivered revocation, historical poisoned attachments, later valid message delivery, same-branch checkpoint access, and ack race. Missing source metadata, changed recipient, missing references/attachments and stale pins still raise explicit errors in `_source_accessible` rather than being mistaken for policy revocation. Generic agent message reads, mailbox, export, events, delivery and withdrawal records do not reveal the revoked private source (`service.py:239-277`, `:1277-1302`, `:1370-1380`).

**Remaining access mismatch:** the withdrawal audit was described as operator-only, but `_in_scope` returns true for every non-agent role before its `discussion_withdrawal` denial (`service.py:209-211`, `:251-252`). A project researcher can read source IDs and reader keys through `get_record`, `page_records` and `export_experiment`; the new test reads it as a researcher (`test_research_discussion.py:324`). This needs an explicit operator/admin gate if operator-only audit is the intended contract. It does not expose these fields to agents in the reviewed paths.

Focused verification actually run for this re-audit: all 21 `test_research_discussion.py` tests plus two runtime withdrawal/ack race tests: **23 passed in 1.32s**.
