# Task A: research board and durable inbox

Implemented `DiscussionMixin` and strict input models. Topics and append-only posts are pinned to the experiment's exact problem revision, target digest and environment digest. Posts preserve the author's ID, source text, artifact IDs, reply target and explicit reference post IDs. Their evidence status is always unverified discussion; the request schema rejects supplied proof status. Cross-branch discussion requires `sharing=ideas` and generic record reads enforce the same rule.

Subscriptions begin at the current event sequence, so historical posts remain available through topic pages but do not flood a new inbox. One reader per experiment and branch persists its acknowledged cursor and at most one pending delivery. The inbox merges subscribed post events with messages addressed to the branch, even if it has no topic subscriptions. Both use the same ordered event sequence and opaque delivery ID. Polls redeliver the exact stored batch until the current batch is acknowledged. Skipped cursors, forged delivery IDs and subscription changes during pending delivery fail. Reads and acknowledgement recheck source scope and artifact access; a policy revocation fails visibly rather than returning a private excerpt.

Each delivery item is an exact UTF-8 source excerpt of at most 1024 bytes with a truncation marker and retrieval ID. The serialized items array is at most 12000 bytes, and paging stops at the last included event. `read_discussion_post` and `read_research_message` retrieve exact full sources under current scope. The generic export includes the new discussion records while excluding another branch's reader and delivery state.

Audit remediation: a source that becomes inaccessible to its reader is represented by a fixed `withdrawal` notice in the same durable delivery. The notice contains the event sequence and reason, with no source ID, artifact ID or original excerpt. A `discussion_withdrawal` record and event retain the internal source link for audit. Scope checks run before the general non-agent access path, so only operator/admin can read this source metadata through get, page, export or events; researcher and agent cannot. Already pending batches are sanitized transactionally on redelivery. If access changes between poll and acknowledgement, acknowledgement first persists the sanitized batch, raises `DELIVERY_CHANGED` without advancing the cursor, and requires the caller to reread and durably save the notice before retrying. Successful acknowledgements report separate delivered and withdrawn counts. Missing or corrupt canonical sources still raise an error. Recipient-facing generic message reads, mailbox pages, event pages and export now hide historical messages with unreadable attachments; this also covers records created before recipient-side attachment admission was added. Same-branch readable checkpoint messages remain deliverable.

Combined discussion/network runtime/API run after the audit gate: 33 passed. Earlier discussion/workforce/network runtime/API/receipt performance run: 47 passed. Ruff check and format passed. SQLite Alembic upgrade through migration 0003 passed.

The initial two general RecordRow indexes raised the cold receipt lookup test from 453 to 585 SQLite instructions at inventory 100. Making the reader and subscription indexes partial by kind retained bounded lookups and restored 453/254/254 instructions for inventory 100/1000/10000 and 284 for a matching receipt. The unchanged receipt performance test passed all three parametrizations. No paid models, VM, credentials, commits or pushes were used.
