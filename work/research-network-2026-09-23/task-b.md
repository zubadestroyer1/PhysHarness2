# Task B: research workforce

Implemented `WorkforceMixin` and strict request models for bounded portfolio seeding, recruitment, opt-in profiles, team labels, capacity demand, and optional cross-topic synthesis. `CollaborationMixin.create_task` now calls the same experiment-locked total/pending admission check as seed, recruit, and synthesis. The original experiment budget and shared ledger remain the only money, time, and concurrency authority. Branch and task creation for seed/recruit/synthesis occurs in one idempotent transaction; no nested service command commits.

Directory output contains only explicitly published summaries, assignment text, interests, and voluntary team labels. It does not return branch objectives or raw profile records. Team membership and capacity requests do not grant access or resources. Capacity reports separate queued tasks, running tasks, and active workers. Recruitment records parent branch, `delegated_from_task_id`, and joined versus detached task lineage. A synthesis task is ordinary queued research work with exact `discussion_refs`, unverified status, and a durable `synthesis_scope` indicating `bounded_sample`, eligible count, sampled count, and through sequence. It does not assert all objections were read or confer proof authority.

Focused validation: `tests/test_research_workforce.py` passed 12 tests; Ruff check passed on owned modules and test. Tests cover atomic rollback, changed-key rejection, legacy cap bypass, concurrent last-slot admission, duplicate concurrent keys, opt-in discovery and generic private-record denial, team leave, demand-only capacity, joined/detached lineage, stale fence denial, cross-experiment source rejection, over-100-post same-topic backlog followed by dissent, and recipient-safe message admission. This is simulated service evidence, not live model or PostgreSQL qualification.

Independent audit follow-up: direct messages now check each attachment against the recipient branch's actual read scope before committing; a private attachment raises `MESSAGE_ATTACHMENT_INACCESSIBLE` without storing a message or event. Automatic joined-child returns keep task evidence intact but omit recipient-private artifact IDs from the parent message's attachment list, JSON content, and failure details, with an explicit `attachments_omitted_for_recipient` marker. This avoids poisoning future inbox delivery while allowing valid child completion. The two added regressions reproduce both paths. `tests/test_research_workforce.py`, `tests/test_sharing.py`, `tests/test_joined_delegation.py`, and `tests/test_research_discussion.py` pass together (89 tests); Ruff passes. Already-persisted inaccessible messages and later access revocation require separate recovery handling by the discussion workstream.

Integration contracts: `HarnessService` composes `WorkforceMixin` in `service.py` (owned by Task A). Task C consumes request models and uses `research_capacity.synthesis_interval_posts` to enable scheduling only for full-root runs. `schedule_research_synthesis` returns an ordinary branch/task under a source branch lineage; active synthesis is discoverable by `task.synthesis == True`. No paid model calls, VM starts, commits, pushes, or credential reads were performed.

Remaining integration checks owned by the root workstream: HTTP/client/MCP contract and full regression suite, optional PostgreSQL concurrency, runtime delivery into model context, and end-to-end fair scheduling. Existing dirty changes were preserved.
