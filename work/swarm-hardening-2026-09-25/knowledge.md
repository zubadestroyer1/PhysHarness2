# Artifact transfer and knowledge work

## Implemented interfaces

- `WorkspaceBroker.promote_file(...)` captures one regular Lean source file under the existing active workspace lease. The request supplies the workspace-relative path, expected SHA-256, and exact current target digest. A successful result is a private `lean_source` artifact with workspace/task/branch provenance and `proof_status: not_accepted`. Capture and artifact insertion share the broker's fenced operation and idempotency key. A repeated successful key returns the same artifact; a repeated definite refusal returns the same refusal. A changed request under the same key conflicts.
- `WorkspaceTools.store_workspace_artifact` exposes capture only to the agent assigned the workspace task. `submit_workspace_candidate` then calls the existing `verify_candidate` as that agent, with a separate idempotent verification key. It returns a queued receipt, never converts local Lean diagnostics to independent acceptance. Both tools are registered by `WorkspaceTools.register(..., agent=agent)` when an agent binding exists. The active worker hook is in `research_worker.py`.
- Local Docker guest capture opens each path component and the final regular file with `O_NOFOLLOW`, requires one link, checks a 4,000,000-byte cap before reading, and checks size/mtime/ctime after reading. A deterministic refusal marker distinguishes unsafe/oversized content from a Docker transport failure, which remains uncertain. E2B capture uses its existing nofollow helper in bounded 32 KiB slices, checks whole-file size/digest on each slice and recomputes the complete digest. Its SDK command output may buffer a single bounded slice internally; this is not a measured streaming-memory claim. No unbounded download fallback is used.
- `search_knowledge` reports `empty_accessible_corpus`, `no_lexical_match`, or `ineligible_or_unavailable_candidate` only where the caller can learn the relevant candidate's existence. On an agent miss it checks the disclosure boundary before distinguishing empty from lexical mismatch; a non-disclosable cross-experiment receipt or corrupt source does not change the diagnostic or expose a rejected claim ID. This miss path can scan additional accepted records and is intentionally slower than successful metadata-first ranking. Lexical matching remains a discovery aid, not a proof of applicability.
- `accepted_proof_summary` exposes a bounded, permission-checked reference only after the existing acceptance/evidence and environment checks. It provides receipt/claim IDs, target and environment digests, candidate SHA-256, bounded statement/assumptions with full-content digests and truncation flags, assurance, and an explicit recomposition requirement. It contains no candidate source or native checkpoint. A model tool registration is provided by the coordination implementation.

## Test evidence

Tests were written to fail for missing promotion/summary/diagnostics before implementation. The focused run of `test_workspace_promotion.py`, `test_execution_e2b_durable.py`, `test_research_services.py`, and `test_knowledge_retrieval_semantics.py` passed 101 tests with two opt-in pinned Docker checks skipped because the endpoint/image environment was absent. A later six-test run passed the added cross-experiment corrupt-proof noninterference regression and exact probe-tool-schema assertions. Tests cover exact bytes and SHA, replay, wrong target/hash, local guest symlink and size refusal, E2B helper chunking/refusal, candidate queued under original agent, accepted-result retrieval/bundle and compact summary, private peer/cross-experiment noninterference, ranking without N+1 proof reads, incompatible assumption/environment/receipt metadata, discovery isolation, and corrupt source rejection. Synthetic verifier fixtures in service tests establish application authority only and are not independent kernel acceptance evidence.

The root ran opt-in tests on the configured pinned local workbench without model calls. The expanded promotion/Lean source reuse/candidate-queue test and unchanged predispatch refusal regression both passed on retry (2 tests, 36.22 seconds). The first suite had two passes and one 90-second timeout in the predispatch Lean regression; the VM was destroyed correctly, and no deadline was changed to hide the failure. Cold-start sensitivity is possible but not established. The real Lean compilation checks local proof reuse; the queued candidate has no independent verification receipt. The real promotion check exercised wrong hash, changed target, and symlink refusal, with the VM still ready afterward. The size limit and other unsafe path refusals were exercised in deterministic provider/unit tests. None of these checks establishes independent acceptance or fleet qualification.

No model or paid VM was started by this implementer. A full-suite run at the first integration point had 1,223 passes, 16 skips, and three failures: the worker hook's legacy test-double signature, a joined-task status shape, and the parallel probe's obsolete expected tool count. The probe assertion was updated to check the exact eight newly registered names; the coordination agent owns the two worker failures. A previous concurrent focused run showed a continuation consumer rejecting the persistence agent's new v2 checkpoint format; that agent was notified, and this is outside these owned files.

## Limits

Promotion supports source up to four million UTF-8 bytes, subject to the existing two-million-character verifier boundary. E2B capture uses multiple bounded SDK calls for larger files, so it is slower than local Docker capture. The operation retains uncertainty for transport failures and lost leases; it treats only confirmed safe helper refusals and local exact-byte/hash/target rejections as definite. Reusing a known premise still requires exact-environment Lean recomposition and independent verification of the complete consuming proof.
